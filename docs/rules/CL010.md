# CL010: Group names a missing job

**Severity:** error

## What is checked?

Every entry under `jobs:` of a group is a job name or a glob (`*`, `deploy-*`, as Concourse matches them). An exact name must exist, and a glob must match at least one job. Both are case-sensitive.

A glob that ends in an unclosed or empty `{}` alternative (`build{`, `build{}`) is also reported: the glob library Concourse uses panics on it for job names of the matching length, so fly crashes and the pipeline cannot be set.

## Example

```yaml
groups:
- name: ci
  jobs: [test, biuld]   # CL010: job "biuld" in group is not defined
```

## Globs that crash fly

Concourse and fly match group entries with `github.com/gobwas/glob` v0.2.3.
That version panics on a glob that ends in an unclosed or empty `{}`
alternative (`build{`, `build{}`, `build{,}`) when it is matched against a
job name of the same length: the empty part of the glob reads one character
past the end of the name. fly then crashes with "slice bounds out of range",
so the pipeline cannot be set or validated.

The bug is known (gobwas/glob#59) and only fixed in the rewritten v1, which
Concourse does not use yet. concourse-lint deliberately uses the same version
as Concourse, so that globs match exactly as they do there, and reports the
glob instead of crashing.

## Fix

Correct the name or the glob. For a glob that crashes fly, close or remove
the braces: `build`, `build-{a,b}`.
