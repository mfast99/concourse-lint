# CL023: Pipeline fragment instead of a pipeline

**Severity:** info

## What is checked?

Whether the file is a fragment of a pipeline: it has `jobs:` with get or put steps, but no top-level `resources:` (and no top-level `<<:` merge key that could bring them). Such files are merged into a pipeline by a tool (spruce, aviator, a script), e.g. one file per job next to a `resources.yml`. Checked alone, every get and put would be a CL002. A fragment gets only this one finding, at its `jobs:` key, and is not checked otherwise. In a folder, fragments are skipped like task files. Broken YAML is no fragment: its CL000 stays.

## Example

```yaml
jobs:               # CL023: no resources: in this file
- name: build-image
  plan:
  - get: ci-dockerfile
  - put: ci-image
```

## Fix

Check the merged pipeline instead: `spruce merge resources.yml jobs/*.yml | concourse-lint check -`. If the file is meant to be a whole pipeline, add its `resources:`.

## Suppress

```yaml
jobs:  # concourse-lint:ignore CL023 -- reason
```

With CL023 off or suppressed, the file is checked like a pipeline. See [suppression](../../spec/README.md#suppression).
