# CL007: file: without an available artifact

**Severity:** error

## What is checked?

The first segment of a `file:` path (task, `load_var`, `set_pipeline`) must be an artifact that is available at this point of the job: fetched by an earlier `get`, produced by an earlier task output, or by the implicit get of an earlier `put`. Artifacts do not carry over between jobs, siblings in `in_parallel` (without `limit: 1`) do not see each other, and the artifacts of a step with `across` stay inside it. After a task from `file:`, whose outputs are unknown, later paths are not checked.

## Example

```yaml
resources:
- name: repo
  type: git
  source: {uri: https://github.com/example/app.git}

jobs:
- name: test
  plan:
  - get: repo
  - task: unit
    file: rpo/ci/unit.yml   # CL007: did you mean "repo"?
```

## Fix

Fetch the artifact in an earlier step, or correct the name.

If a `get` or `put` earlier in the job has a misspelled resource (CL002), its artifact is missing too. The hint then points to that step: fixing it there fixes both findings.
